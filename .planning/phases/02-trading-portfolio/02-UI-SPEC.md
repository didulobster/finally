# Phase 02 — UI Design Contract

> Visual and interaction contract for the Trade bar, Positions table, Heatmap, P&L chart and the live header total. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: `02-CONTEXT.md` (D-01..D-11 locked, heatmap/layout/empty states at Claude's discretion), `02-RESEARCH.md` (stack, pitfalls), `planning/PLAN.md` §2/§10 (colors, layout), the binding E2E specs `test/e2e/03-trading.spec.ts` and `04-portfolio-viz.spec.ts`, and the existing Phase 1 code (`frontend/app/globals.css`, `components/Panel.tsx`, `Header.tsx`, `Watchlist.tsx`, `store/format.ts`). Existing Phase 1 tokens and components are reused as they are. This contract adds no new theme tokens.

## Spacing Scale

Declared values (all multiples of 4, as Tailwind 4 spacing utilities):

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `gap-1`, `p-1`, `py-1` | Grid gaps between panels (existing), heatmap tile inner padding, positions row vertical padding |
| sm | 8px | `gap-2`, `px-2`, `py-2` | Gap between trade inputs and buttons, input horizontal padding, table cell horizontal padding |
| md | 12px | `px-3` | Panel body horizontal inset (matches Phase 1 panel title `px-3` and `PanelNote` `p-3`) |
| lg | 16px | `gap-4`, `px-4` | Gap between the Sell button and `trade-result`, button horizontal padding |
| xl | 24px | `gap-6` | Header stat spacing (existing, unchanged) |
| 2xl | 32px | `h-8` | Height of trade inputs and Buy/Sell buttons |

Fixed sizes that are multiples of 4: panel title bar `h-7` (28px, existing), table header row `h-7` (28px), positions data row 28px (`py-1` + 20px line), trade input width `w-24` (96px), Buy/Sell button width `w-16` (64px), heatmap/P&L minimum height `min-h-40` (160px).

Exceptions:
- The existing Phase 1 watchlist row uses `py-1.5` (6px). It is inherited and left untouched, and no Phase 2 component may reuse it.
- Heatmap tile positions and sizes are percentages from the treemap layout and are not on the spacing scale. Tile separation is a 1px `border-bg` border, not a gap.

## Typography

Exactly 4 sizes and 2 weights. These sizes already exist in the Phase 1 code, so no new sizes are introduced.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Heading (panel title, table column header) | 11px (`text-[11px]`), uppercase, `tracking-widest`, `text-muted` | 400 | 1.5 (inherited, ~16px) | Existing panel titles; the positions table `<th>` row uses the same style |
| Label (small copy) | 12px (`text-xs`) | 400 | 16px (Tailwind `text-xs` default, 1.33) | `trade-result`, empty/loading notes (`PanelNote`), header stat labels, heatmap tile P&L % |
| Body (data) | 14px (`text-sm`) | 400. Tickers and button labels use 600 | 20px (Tailwind `text-sm` default, 1.43) | Positions rows, trade inputs, Buy/Sell labels, heatmap tile ticker |
| Display (header values) | 16px (`text-base`) | 400 | 24px (1.5) | Header `total-value` and `cash-balance` (existing) |

Weights: 400 (regular) for everything by default, and 600 (`font-semibold`) only for the ticker symbol in positions rows and heatmap tiles, the Buy/Sell button labels, and the existing `FinAlly` wordmark.

Numerals: use `font-mono tabular-nums` for every price, quantity, P&L, percent and input value, so columns do not jitter on ticks.

## Color

All values are existing `@theme` tokens in `frontend/app/globals.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d1117` (`bg-bg`) | Page background, the gaps between panels, trade input fields, heatmap tile separators (`border-bg`) |
| Secondary (30%) | `#1a1a2e` (`bg-panel`) | Header, every Panel surface (Trade, Heatmap, P&L, Positions), the sticky table header row |
| Accent (10%) | `#ecad0a` (`text-accent` / `bg-accent`) | Reserved elements only (list below) |
| Buy / Sell buttons | `#3fb950` (`bg-up`) / `#f85149` (`bg-down`), label `text-bg` | Buy is green and Sell is red (user decision 2026-09-26, the terminal convention). This overrides PLAN.md's purple-submit rule for these two buttons only; `bg-submit` purple stays reserved for later submit buttons (e.g. chat send). Dark `text-bg` labels give about 8.7:1 contrast on green and 5.9:1 on red. |
| Primary / focus | `#209dd7` (`border-primary`, `outline-primary`) | Focus ring on trade inputs and the Buy/Sell buttons (`focus-visible`) |
| Up / profit / success | `#3fb950` = `rgb(63, 185, 80)` | Positive P&L and % text, successful buy `trade-result`, "up" heatmap tiles, the P&L area when latest ≥ first snapshot |
| Destructive / loss / error | `#f85149` = `rgb(248, 81, 73)` | Negative P&L and % text, rejected `trade-result`, "down" heatmap tiles, the P&L area when latest < first snapshot. No destructive actions exist in this phase. |
| Flat / neutral | `#30363d` = `rgb(48, 54, 61)` (`border-border`) | Borders, table row dividers, "flat" heatmap tiles, chart grid lines |
| Text | `#e6edf3` (`text-text`) | Primary text, heatmap tile text, button labels, successful sell `trade-result` (user decision 2026-09-26, UAT G-02-3) |
| Muted | `#8b949e` (`text-muted`) | Panel titles, column headers, empty/loading notes, zero P&L, the idle `trade-result` hint, chart axis text, input placeholders |

Accent (`#ecad0a`) is reserved for:
1. The `FinAlly` wordmark in the header (existing)
2. The "reconnecting" connection-status dot (existing)
3. Hover on the chat drawer collapse/expand toggle (existing)

Accent is **not** used by any Phase 2 element. Buy/Sell use up green / down red, focus uses primary blue, and data uses up/down.

Heatmap and chart color rule (binding, from 02-RESEARCH Pitfall 1): set tile backgrounds with **inline `rgb()`/`rgba()` strings**, never Tailwind opacity modifiers (`bg-up/60`) or Tailwind palette classes (`bg-green-600`). Chromium serializes those as `oklab()`/`oklch()`, which breaks the spec 04 channel parser.
- up: `rgba(63, 185, 80, a)`, down: `rgba(248, 81, 73, a)`, flat: `rgb(48, 54, 61)`
- intensity `a = Math.min(1, 0.35 + Math.abs(pnlPercent) / 5)`, so a ±3.25% move is fully saturated
- Derive `data-pnl` and the color from the same number: `pnl > 0 ? "up" : pnl < 0 ? "down" : "flat"`

## Layout & Component Contracts

The Phase 1 grid in `frontend/app/page.tsx` is unchanged, except that the Trade panel has no fixed height at md and up and sizes to the trade bar (UAT G-02-1). This phase only replaces four `PanelNote` bodies, and the panel titles stay `Trade`, `Heatmap`, `P&L` and `Positions`. The E2E viewport is 1600×1000, i.e. the desktop grid.

### Trade bar (`components/TradeBar.tsx`, inside the Trade panel, which sizes to the bar: a 64px body on one row, taller when the bar wraps)

- Body: `flex min-h-16 flex-wrap items-center gap-2 px-3`. It sits on one row when the middle column is wide enough (about 900px and up with the chat drawer open) and wraps otherwise; the panel grows with the rows, so Buy and Sell are never clipped (UAT G-02-1).
- Order, left to right: ticker input, quantity input, Buy, Sell, then `trade-result` (`ml-2 min-w-0 flex-1`, which with the gap-2 gives the 16px separation).
- `trade-ticker`: `<input type="text">`, `aria-label="Ticker"`, placeholder `Ticker`, `h-8 w-24 border border-border bg-bg px-2 font-mono text-sm uppercase`. CSS `uppercase` is for display only; the raw value is sent and the backend normalizes it.
- `trade-quantity`: `<input type="number" step="any" min="0">`, `aria-label="Quantity"`, placeholder `Qty`, same style as the ticker input.
- Inputs on focus: `focus:border-primary focus:outline-none`. Placeholder `placeholder:text-muted`.
- `trade-buy` / `trade-sell`: `<button type="button">`, labels `Buy` / `Sell`, `h-8 w-16 text-sm font-semibold text-bg hover:brightness-110 active:brightness-90 focus-visible:outline focus-visible:outline-2 focus-visible:outline-primary`, with `bg-up` on Buy and `bg-down` on Sell. Both have `aria-label` `Buy shares` / `Sell shares`, and the visible labels stay `Buy` / `Sell`.
- Both buttons stay enabled at all times, including while a request is in flight (D-04). There is no `<form>` element, so Enter does not submit (this avoids an ambiguous Buy/Sell on Enter).
- After a success both inputs keep their values (D-01).
- `trade-result`: `<p role="status" aria-live="polite">`, `truncate text-xs font-mono`, with `title={text}` so the full text shows on hover. It is always rendered, and four states follow in the copy table: idle (`text-muted`), buy success (`text-up`), sell success (`text-text`, neutral), rejected (`text-down`). It persists until the next trade and has no fade timer (D-02).
- The store is written only on `r.ok` (D-06). A rejection leaves cash and positions untouched (TRAD-02).

### Positions table (`components/Positions.tsx`)

- A semantic `<table className="w-full font-mono text-sm tabular-nums">`.
- `<thead>`: `sticky top-0 bg-panel`, row `h-7`, cells `px-2 text-[11px] uppercase tracking-widest text-muted font-normal` (the font-sans heading style).
- Columns in order, with header copy: `Ticker` (left) · `Qty` · `Avg Cost` · `Price` · `P&L` · `%` (all numeric columns right-aligned).
- Row: `<tr data-testid="position-row-{TICKER}" className="border-b border-border">`, cells `px-2 py-1`. The ticker cell is `font-semibold`. The Qty cell carries `data-testid="position-qty-{TICKER}"`.
- Values: Qty `formatQty` · Avg Cost `formatPrice(avg_cost)` · Price `formatPrice(live)` · P&L `formatSignedPrice((live − avg_cost) × qty)` · % `formatPercent((live − avg_cost) / avg_cost × 100)`.
- P&L and % color: `text-up` if > 0, `text-down` if < 0, `text-muted` if 0. Ticker, Qty, Avg Cost and Price use `text-text`.
- Live price is `prices[ticker]?.price ?? current_price` (D-05). Price, P&L and % update on every tick. Qty and Avg Cost change only on a trade (D-07).
- Rows are sorted alphabetically by ticker and never reorder on ticks (D-08). A position sold to zero is absent from the returned portfolio, so its row disappears.
- Overflow: the Panel body already scrolls (`overflow-auto`), and the sticky header stays visible.

### Heatmap (`components/Heatmap.tsx`)

- Container: `<div data-testid="heatmap" className="relative h-full min-h-40">` (definite height; Pitfall 6).
- Layout: `d3-hierarchy` `treemap().size([1, 1]).tile(treemapSquarify)` over the positions, with value = `quantity × livePrice` (market-value weight of the invested positions; cash excluded), sorted by value descending. It is recomputed in render on every tick, with no measuring, ResizeObserver or effect.
- Tile: `<div data-testid="heatmap-cell-{TICKER}" data-pnl="up|down|flat">`, `absolute overflow-hidden border border-bg p-1`, with inline `left/top/width/height` as percentages of the leaf rect and an inline `backgroundColor` per the Color rule. `title` is `"{TICKER} · {formatPrice(value)} · {formatPercent(pct)}"`.
- Tile content (stacked, left/top aligned): the ticker `text-xs font-semibold text-text font-mono`, then the P&L % `text-[11px] text-text font-mono tabular-nums` (`formatPercent`). Content that does not fit a small tile is clipped by `overflow-hidden`, and nothing wraps or shrinks.
- There is no hover state, no click action and no animation. Tiles repaint in place on every tick.

### P&L chart (`components/PnlChart.tsx`)

- Wrapper: `<div data-testid="pnl-chart" data-points={points.length} className="relative h-full min-h-40">`, holding a mount `<div ref className="absolute inset-0" />` with **no React children** (LWC owns its DOM).
- Chart options: `autoSize: true`, `layout: { background: { type: ColorType.Solid, color: "transparent" }, textColor: "#8b949e", fontSize: 11 }`, `grid: { vertLines: { visible: false }, horzLines: { color: "#30363d" } }`, `rightPriceScale: { borderColor: "#30363d" }`, `timeScale: { borderColor: "#30363d", timeVisible: true }`, `localization: { priceFormatter: formatPrice }`. Leave `attributionLogo` at its default, which keeps the license attribution.
- Series: `addSeries(AreaSeries)`. When the latest value is ≥ the first snapshot, use `lineColor: "rgb(63, 185, 80)"`, `topColor: "rgba(63, 185, 80, 0.4)"`, `bottomColor: "rgba(63, 185, 80, 0)"`. Otherwise use the same three with `248, 81, 73` (D-11). `lineWidth: 2`.
- Data: snapshots only, with no appended live point (D-10). Dedupe to one point per whole second (last wins; Pitfall 2). Call `fitContent()` after every `setData`.
- Refresh: fetch on mount, after each successful trade, and every 30 s (D-09).

### Header total (`components/Header.tsx`)

- `total-value` = `selectTotalValue` (cash + Σ qty × live price), a primitive selector (HDR-02). The markup and style are unchanged from Phase 1 (16px mono, `text-text`). The value is not colored and does not flash (flash is v2).

### Number formatting (`store/format.ts`, en-US, extends Phase 1)

| Formatter | Rule | Example |
|-----------|------|---------|
| `formatPrice` (existing) | USD currency, 2 decimals | `$190.12`, `$10,000.00` |
| `formatPercent` (existing) | sign except zero, 2 decimals, `%` | `+1.25%`, `-0.40%`, `0.00%` |
| `formatQty` (new) | `Intl.NumberFormat("en-US", { maximumFractionDigits: 4 })` | `5`, `2.5`, `1,000` (matches `/\b5(\.0+)?\b/`) |
| `formatSignedPrice` (new) | USD currency, 2 decimals, `signDisplay: "exceptZero"` | `+$12.34`, `-$8.10`, `$0.00` |

| Element | Copy |
|---------|------|
| Primary CTA | `Buy` and `Sell` (buttons `trade-buy` / `trade-sell`; the verb is the action, the object is the typed ticker) |
| Trade input placeholders | `Ticker` · `Qty` |

| Heatmap empty | `No holdings to map. Each position appears here sized by its value.` (`PanelNote`) |
| Heatmap loading (`cash === null`) | `Loading holdings…` (`PanelNote`) |
| P&L chart empty (history not yet loaded) | `Waiting for the first portfolio snapshot…`. This is rendered as a muted `PanelNote` overlay (`absolute inset-0`) inside the `pnl-chart` wrapper, so the wrapper and canvas mount exist at all times. |
| Positions column headers | `Ticker` · `Qty` · `Avg Cost` · `Price` · `P&L` · `%` |
| Destructive confirmation | None. There are no destructive actions in this phase, and trades are never confirmed (PLAN.md §2, REQUIREMENTS "Out of Scope": no trade confirmation dialogs). |

## Interaction Summary

| Interaction | Behavior |
|-------------|----------|
| Click Buy / Sell | POST `/api/portfolio/trade` with the raw ticker, `Number(qty)` and the side. On success, update the store from the response `portfolio`, show the result line (green for a buy, neutral text for a sell) and refetch history. On failure, show the red result and leave the store unchanged |
| Price tick (~500 ms) | Header total, positions Price/P&L/% and heatmap tiles recompute from `prices`. Rows never reorder. The P&L chart does not change |
| Keyboard | Tab order: ticker → quantity → Buy → Sell. The focus-visible ring is `primary` blue. Enter does not submit |
| Hover | Buy/Sell brighten (`brightness-110`). Heatmap tiles and a truncated `trade-result` show a native `title` tooltip. Table rows have no hover effect |
| Motion | None added in this phase (price flash is v2) |
