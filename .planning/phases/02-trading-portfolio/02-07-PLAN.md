## Phase Goal

ROADMAP Goal (verbatim): The user can trade from the trade bar and see the result across the portfolio: cash, positions table, heatmap, P&L chart, and live total value.

Note: this Goal is not in user-story format. As in 02-03 to 02-06, the planner did not invent a story and did not rewrite the ROADMAP goal. The vertical-slice rules still apply: Task 1 is a tracer from the unit test through the selector and Header to a served build, and Task 2 carries the same fix into the image the user runs.

<objective>
Close the one remaining gap, G-02-5: the header total must not depend on the order positions are summed, proven by a unit test.

The shipped selectTotalValue adds the positions as floats. Near a half-cent, the displayed total therefore depends on the order: the same state shows "$11,899.15" in order A,B,C and "$11,899.14" in order B,A,C. The 02-05 test passes on this code because its only fixture sits far from a rounding boundary (review WR-01). The user decided on 2026-09-27 to fix the code rather than weaken the truth.

Purpose: HDR-02's live total gets an order-independence property that is actually true. The fix is to sum in integer cents, which is exact. This also matches the backend's per-position rounding.
Output: an integer-cents selectTotalValue, a test file that fails on the old reduce and passes on the fix, a two-line UI-SPEC sync, and the `finally` image tag re-proven on the compose path.
</objective>
