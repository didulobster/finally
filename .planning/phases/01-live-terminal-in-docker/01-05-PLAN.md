## Phase Goal

ROADMAP Goal (verbatim): One `docker run` opens a dark trading terminal on :8000 that shows the 10 default tickers with streaming prices, $10k cash, and a connection status dot that survives a network drop.

The user accepted this goal wording in UAT Test 5, so no user story is added.

<objective>
Close UAT gap G-01-2 (code-review WR-01). The live price stream must recover without a page reload even when a reconnect attempt gets a non-200 response, for example a 502 from a proxy during a redeploy.

Purpose: per the WHATWG spec, confirmed in Chromium, a non-200 or non-event-stream response closes the EventSource for good (readyState CLOSED), and the browser stops retrying. connect() has no path out of CLOSED, so the dot stays OFFLINE and prices freeze until a reload. That breaks ROADMAP SC3 and HDR-04.

Decision note: D-10 said to rely on native auto-retry with no custom reconnect timers. In UAT Test 2 the user chose "fix it now" for the option "reopen the EventSource after CLOSED". That amends D-10 for the CLOSED state only, where the browser has already stopped retrying. The CONNECTING path, and exactly one live EventSource, stay as D-10 specifies.
Output: a committed 502 probe that is proven red on the old store, the reopen fix in frontend/store/terminal.ts proven green, and the binding reconnect spec still passing.
</objective>

Step A: write the probe, test/sse-502-probe.mjs. It is a plain Node ESM script, run as `node test/sse-502-probe.mjs <app-url>`, with the app URL defaulting to http://127.0.0.1:8000. It is not a spec file and lives outside test/e2e, so the Playwright runner never picks it up.

Proxy:
- A node:http server on 127.0.0.1, port 0. It forwards every request to the app with http.request (same method, url, and headers) and pipes the status, headers, and body back as a stream.
- It tracks the open responses for /api/stream/prices.
- It has a mode flag. When failing, any /api/stream/prices request gets an immediate 502 with a short text/plain body, and the probe counts these 502s.
- A fail() helper sets failing mode and destroys every tracked stream response, so the browser sees the stream drop and retries into the 502.
- A restore() helper clears failing mode.

Browser:
- Launch chromium and open a page at 1600x1000.
- Before the app script runs, add an init script that replaces window.EventSource with a subclass. Use a subclass so EventSource.CLOSED still resolves. The subclass pushes each instance into window.__es.
- A 100 ms interval in the page records window.__maxLive, the highest count of instances whose readyState is not 2.

Stages, in order. Each waits up to 15 s, using page.waitForSelector on `[data-testid="connection-status"][data-status="..."]` or a short poll:
1. connect: go to the proxy URL, wait for connected, and wait for watchlist-price-TSLA to contain a digit.
2. outage: call fail() and wait for disconnected.
3. hold: stay in failing mode for 5 more seconds.
4. recover: call restore() and wait for connected.
5. prices: read the TSLA price text, then poll until it differs.
6. single: require __maxLive to be exactly 1, at least 2 EventSources created, and at least 2 proxied 502s. That means reopening actually happened during the outage.

Output: on success print one line `sse-502-probe: PASS created=N maxLive=M 502s=K` and exit 0. On failure print one line `sse-502-probe: FAIL stage=<stage> status=<data-status> created=N maxLive=M 502s=K` and exit 1. Always close the browser and the proxy.
