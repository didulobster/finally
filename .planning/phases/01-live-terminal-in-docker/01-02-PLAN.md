<interfaces>
Backend contracts this plan consumes (unchanged unless 01-01 fixed a gap, see 01-01-SUMMARY.md):
- GET /api/watchlist -> JSON array in watchlist seed order. Each item is PriceUpdate.to_dict() {ticker, price, previous_price, timestamp, change, change_percent, direction ("up"|"down"|"flat"), open_price, session_change_percent}, or {ticker, price: null} when uncached (backend/app/api.py get_watchlist).
- GET /api/portfolio -> {cash_balance, positions, positions_value, total_value, unrealized_pnl} (backend/app/portfolio.py get_portfolio).
- GET /api/stream/prices -> "retry: 1000" first, then "data: {TICKER: {...same keys...}}" about every 500 ms. Content-Type text/event-stream. It also carries held tickers that are not on the watchlist (backend/app/market/stream.py).
- FastAPI mounts SPAStaticFiles at / when STATIC_DIR exists (backend/app/main.py). The Dockerfile sets STATIC_DIR=/app/backend/static and copies /frontend/out there.

E2E contract (test/e2e/helpers.ts, 01-fresh-start.spec.ts, 06-sse-reconnect.spec.ts):
- parseNumber(text) removes every character except digits, ".", and "-" (U+2212 becomes "-"). One number per testid element.
- openApp waits for connection-status data-status="connected". The cash-balance and total-value checks read once, with no retry.
- [data-testid^="watchlist-row-"] must count exactly 10. waitForPrice waits for a digit in watchlist-price-{T}.
- 06 loads the page through a TCP proxy on 127.0.0.1 and a random port, drops the sockets, expects data-status to leave "connected", then expects "connected" again within 20 s and a TSLA price change within 15 s.

frontend/store/terminal.ts (D-09, D-10, D-08, D-12):
- Export the type `Status` as "connected" | "reconnecting" | "disconnected".
- Export the type `Price`, mirroring the models.py keys: ticker, price, previous_price, timestamp, change, change_percent, open_price, session_change_percent as numbers, and direction as "up" | "down" | "flat".
- Export the type `TerminalState` with: status (Status), prices (Record of ticker to Price), watchlist (string array), cash (number or null), and totalValue (number or null).
- Export `useTerminal`, built with zustand `create<TerminalState>()`. Initial state: status "reconnecting" (research open question 2, resolved), empty prices, empty watchlist, and null cash and totalValue.
- Export `connect(): () => void`, which does three things:
  - fetch "/api/watchlist": set watchlist to the tickers in response order, and seed prices only from items whose price is not null. Merge the seed under existing entries so SSE ticks that arrived first win.
  - fetch "/api/portfolio": set cash from cash_balance and totalValue from total_value.
  - Construct exactly one EventSource on "/api/stream/prices". onopen sets "connected". onerror sets "disconnected" when readyState equals EventSource.CLOSED, otherwise "reconnecting". onmessage merges the parsed JSON object over prices, replacing each ticker's object.
  - Return a cleanup that closes the EventSource.
- No timers of any kind, no manual reconnect, no second EventSource: rely on native retry (D-10).
- Use relative "/api/..." strings only (D-12). The frontend reads no environment variables.
- Add a one-line JSDoc on each export.
